Screenshots


All five are captured from the live instance, not from mock-ups.
PageWhat it shows |---|---| `/` — the PayPal sandbox checkout button. The web payment path: the buyer approves in the PayPal popup and the page captures the order to `COMPLETED`. `/constraints` — one sentence in, structured rules out. The rule cards show the parsed monthly budget, per-transaction threshold, daily threshold and both allowlists; the demo panel below runs the same sentence through the agent. `/approvals` — the human-authorisation half of the loop. Each request carries its decision badge; the `PENDING_HUMAN` one offers the "Go to PayPal" + "I paid, capture it" button pair. `/audit` — every transaction as three cards. One row per transaction, showing the Intent / Cart / Payment layers side by side under a shared `trace_id`, with all three verdicts visible. `/budget` — the AG Studio dashboard. Monthly budget, committed spend, remaining and projected month-end, all computed from the same records. If the AG Studio runtime cannot load, the page falls back to a hand-built classic view automatically.

The three scenarios (expected decisions)


With the default constraints — monthly budget $200, per-transaction threshold $50, vendor allowlist [Notion, Figma]:
